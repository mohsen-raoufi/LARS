## Project Overview

LARS (Light Augmented Reality System) is a Qt/C++ application for collective robotics research. It detects and tracks physical robot swarms (Kilobots, Thymios, e-pucks) via overhead camera and overlays virtual environments via projection. Target platforms: Ubuntu x86 and NVIDIA Jetson ARM64.

## Build Commands

```bash
# Configure (run from repo root)
qmake LARS.pro

# Build
make -j$(nproc)

# Run (macOS)
./LARS.app/Contents/MacOS/LARS

# Run (Linux)
./LARS
```

There is no test suite — validation is done via Python scripts in `etc/validation/`.

## Build Configuration (LARS.pro)

Key `DEFINES` to toggle in `LARS.pro` before running `qmake`:

| Define | Purpose |
|--------|---------|
| `USE_OPENCV3` | OpenCV 3 compatibility mode (default is OpenCV 4) |
| `FOR_KILOBOT` | Target Kilobot robots (alternatives: `FOR_THYMIO`) |
| `USE_PYLON` | Enable Basler Pylon professional camera support |
| `USE_CUDA` | Enable GPU-accelerated tracking (requires CUDA-built OpenCV) |

The `Makefile` is auto-generated by `qmake` — do not edit it directly.

**Jetson:** OpenCV must be compiled from source with `-D WITH_CUDA=ON` for GPU tracking to work.

## Architecture

LARS follows MVC with Qt signals/slots connecting all subsystems:

```
main.cpp
└── MainWindow (orchestrator, UI event hub)
    ├── KilobotTracker       — camera input, Hough circle detection, LED color ID, tracking
    ├── EnvBrain             — virtual environment: heatmaps, noise, spatial utilities
    ├── KilobotOverheadController — serial comms to OHC hardware, message queuing
    ├── WorldModel           — shared state: robot positions, arena geometry, heatmap data
    └── ArenaWindow / RenderArea — Qt QPainter rendering, projector output, Voronoi/graphs
```

### Key Components

**`tracker/robottracker.cpp`** — Core vision pipeline. Acquires frames in a background thread (`acquireThread`), applies image warping/stitching for multi-camera setups, runs Hough circle detection for robot localization, and classifies robots by LED color. Conditionally compiles CUDA paths (`#ifdef USE_CUDA`) using `cuda::GpuMat` vs CPU `UMat`.

**`envbrain.h/cpp`** — Drives the virtual environment. Generates and updates heatmaps, Perlin-like noise fields, and geometric patterns. Connected to Qt timers for periodic refresh.

**`ui/worldmodel.h`** — Central data store (not a Qt model in the MVC sense, just a struct-like container). Holds arena dimensions (1030×1030 Kilobots, 1560×930 Thymios), calibration marker positions, robot position/color vectors, heatmap `cv::Mat`, and all rendering flags (`drawTrace`, `drawHeatMap`, `drawVoronoi`, etc.).

**`ui/renderarea.h/cpp`** — Custom `QWidget` that renders the arena display using `QPainter`. Draws robot positions, heatmap overlays, Voronoi tessellations (via Boost.Polygon in `ui/geom/voronoiGenerator.h`), network graphs (via igraph), and robot traces.

**`Kilobot/kilobot.h`** — Individual robot agent. Maintains `ColourBuffer`, `OrientationBuffer`, `PositionBuffer` circular buffers for temporal smoothing of sensor readings.

**`Kilobot/kilobotoverheadcontroller.h/cpp`** — Manages serial connection to the overhead infrared controller (OHC). Handles message queuing, broadcast to swarm, firmware upload (Intel HEX format), and per-robot commands.

**`ohc/serialconn.h/cpp`** — Low-level serial communication layer underneath `KilobotOverheadController`.

### Signal/Slot Flow

Robot tracking frames flow: `KilobotTracker` emits detected positions → `MainWindow` slot updates `WorldModel` → triggers `RenderArea::update()` for repaint → `MainWindow` also forwards robot positions to `KilobotOverheadController` for feedback loop to hardware.

### Experiment API

Custom experiments subclass `KilobotExperiment` (defined in `Kilobot/kilobotexperiment.h`) and `KilobotEnvironment` (`Kilobot/kilobotenvironment.h`). These interfaces receive per-robot position/state callbacks and can inject messages back to the swarm via the OHC.

## Platform Notes

**NVIDIA Jetson (dev-nvidia branch):**
- User must be in `dialout` group for serial port access: `sudo usermod -a -G dialout $USER`
- CSI camera requires GStreamer pipeline configuration
- CUDA tracking requires OpenCV built from source with CUDA support

**macOS:** Serial OHC communication requires USB-serial adapter drivers.
